# Bind one socket per selected listen interface instead of `0.0.0.0` plus peer filtering

Upstream's exposure model is two-valued: loopback, or `0.0.0.0` with Tailscale integration. The fork models exposure as a set of listen-interface kinds — `loopback` (always), `tailnet`, `lan`, plus an optional explicit IP list for a `custom` preset — carried through the contract and CLI as `listenInterfaces`. The server resolves kinds to concrete addresses at launch (via `@t3tools/tailscale`'s `isTailscaleIpv4Address`, no `tailscale` CLI dependency) and opens one listen socket per resolved address; if the tailnet is absent at launch it binds loopback only and warns. Any non-loopback interface implies the `remote-reachable` auth policy; advertised endpoints are derived from the selection; changing exposure still relaunches the backend; there is no peer allowlist in v1.

True per-interface binding was chosen because the kernel enforces it — a filtered `0.0.0.0` listener is still a listener. Kinds were chosen over raw IPs (DHCP changes them) and over OS interface names (`en0`, `tailscale0`; OS-specific), and server-side resolution keeps one implementation for desktop, CLI `--host`, and the WSL backend. Escape hatch: only if `HttpServerLive` cannot be instantiated once per address do we fall back to `0.0.0.0` with a `socket.localAddress` check.

**Interim (2026-09-15, retired by ticket #6).** While the server still opens a single socket, a selection that contains a non-loopback kind binds its first non-loopback resolved address and does not bind loopback; `--host tailnet` therefore listens on the tailnet address only. This contradicts "loopback (always)" above on purpose: the alternatives were binding loopback only (making the tracer useless) or `0.0.0.0` (exposing more than asked). Multi-bind restores loopback alongside every selected interface.
