# Identify skills by `{ source kind, name }` and disable them in T3 Code only

T3 Code needs per-skill enable/disable across every provider that discovers skills. A skill is identified by the pair `{ source, name }` — the provider-agnostic source kind from `resolveProviderSkillSourceKind` and the trimmed, case-insensitive name (the normalization the skill picker's dedupe already uses). The disabled set is a server setting with per-project overrides that *replace* (not merge) the global list, and it is applied once at the `ProviderRegistry` publish chokepoint by folding into `ServerProviderSkill.enabled` with `disabledBy: "provider" | "settings"`. T3 Code never writes provider configuration (`~/.claude/settings.json` skill overrides, Grok `userInvocable`, …): a disabled skill is hidden from pickers and `$name` dispatch, but the provider may still auto-invoke it, and the UI says so.

Path identity was rejected because it breaks on worktrees (one path per thread checkout), provider upgrades (version-stamped bundled skill dirs), moves/renames, symlinks, and case-insensitive filesystems. Bare-name identity was rejected because it cannot separate a Personal `review` from a Project `review`. Writing provider config was rejected because it races with the CLIs' own settings and has no uniform expression across providers. Consequences: same-named skills in two roots of the same kind are disabled together; a skill seen by two providers is disabled for both; a manually typed `$name` for a disabled skill is sent as prose.
