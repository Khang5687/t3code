# Identify skills by `{ source kind, name }` and disable them in T3 Code only

T3 Code needs per-skill enable/disable across every provider that discovers skills. A skill is identified by the pair `{ source, name }` — the provider-agnostic source kind from `resolveProviderSkillSourceKind` and the trimmed, case-insensitive name (the normalization the skill picker's dedupe already uses). The disabled set is the `disabledSkills` server setting, registered in `PROJECT_SCOPED_SERVER_SETTING_KEYS` so a project override lives in `projectSettingsOverrides` and _replaces_ (not merges) the environment list; a dedicated per-project map was dropped because upstream had just replaced every such map with the scoped-key mechanism. The fold (`resolveEffectiveSkills` in `packages/shared`) runs at the service boundary, never into stored state, so a skill can be switched back on: `ProviderRegistry` folds the environment list on publish into `ServerProviderSkill.enabled` with `disabledBy: "provider" | "settings"`, and `ProviderService` folds the thread's project list on the send path. Cursor is the one adapter that rewrites `$name` itself, so its send-path fold runs before that rewrite. T3 Code never writes provider configuration (`~/.claude/settings.json` skill overrides, Grok `userInvocable`, …): a disabled skill is hidden from pickers and `$name` dispatch, but the provider may still auto-invoke it, and the UI says so.

Path identity was rejected because it breaks on worktrees (one path per thread checkout), provider upgrades (version-stamped bundled skill dirs), moves/renames, symlinks, and case-insensitive filesystems. Bare-name identity was rejected because it cannot separate a Personal `review` from a Project `review`. Writing provider config was rejected because it races with the CLIs' own settings and has no uniform expression across providers. Consequences: same-named skills in two roots of the same kind are disabled together; a skill seen by two providers is disabled for both; a manually typed `$name` for a disabled skill is sent as prose.
