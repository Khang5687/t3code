# Run pxpipe as a pinned, environment-supervised sidecar with per-instance opt-in that fails routed turns fast

`pxpipe-proxy` is a local HTTP proxy that serves the Anthropic Messages API on `127.0.0.1:47821` and forwards to a configured upstream. The fork runs one sidecar per environment: a pinned `pxpipe-proxy@0.13.2` installed with `npm install --prefix` into a T3-owned cache (`<T3CODE_HOME>/sidecars/pxpipe/<version>/`, staged then renamed into place behind a completion sentinel, as `runtime/versions` does) and run from its `node_modules/.bin/pxpipe`, with a `binaryPath` override, started at boot when enabled, restarted with capped backoff, and health-checked with `GET /proxy-stats`. Each Claude provider instance opts in individually (a _routed instance_); routed instances receive `ANTHROPIC_BASE_URL=http://127.0.0.1:<configured port>` for SDK sessions, text generation, provider status probes and T3 terminals, unless an explicit `ANTHROPIC_BASE_URL` is already set on the instance or inherited from the server process, in which case that value wins and the instance card says routing is inactive. One function applies the rule (`applyPxpipeRouting`), called where an instance's environment is assembled from settings, so no path can drift. Setting `ANTHROPIC_BASE_URL` costs Claude Code's first-party client gates — `/remote-control` and claude.ai connectors stop working on a routed instance — which the switch's own description states; wrapping every spawn in `pxpipe warp` would keep them, at the price of a command builder at each spawn site instead of one environment rule. When the sidecar is unhealthy, routed turns fail fast with a "Start proxy" action — they never silently fall back to the direct upstream. Configuration is a typed core plus an `extraEnv` list whose `sensitive` entries live in `ServerSecretStore`.

Pinning plus a version cache makes the sidecar reproducible and safe offline after first run; per-instance opt-in keeps unrouted instances byte-identical to upstream behaviour; failing fast prevents traffic bypassing a proxy the user configured for routing or billing reasons. Rejected: `npx --package`, whose cache belongs to npm rather than to T3 Code and carries no completion sentinel, so a killed fetch cannot be told from a good one; a global on/off switch (cannot mix routed and unrouted instances); silent fallback to upstream; and a user-managed external daemon.
